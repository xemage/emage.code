# Release v8.0.0

## Summary

v8.0.0 is a major release of the emage.code harness since v7.0.1. It corrects and pins the extended MCP server entries (four launchers named npm packages that do not exist), removes the `fetch` server and hardens the `playwright` server, makes the installer refuse symlinked managed paths, adds the `poc-security-audit` server and a blocking PoC security review, tightens the gate and PoC rules, and moves the release procedure to one release document. Read the Migration Guide before you run `--update`; section M-9 applies to v7.x installs today.

## Install

Latest release: v8.0.0

Install with the installer from a clone of this repository:

```bash
git clone https://gitlab.com/em-age/emage.code.git
cd emage.code
scripts/install.sh --target <your-project> --platform <name>
```

| Platform | `--platform` value |
|----------|-------------------|
| Cursor | `cursor` |
| GitHub Copilot (VS Code) | `github` |
| Gemini CLI | `gemini` |
| Opencode | `opencode` |
| Pi | `pi` |
| Claude Code | `claude-code` |
| Cline | `cline` |
| All platforms | `all` |

Update an existing install: add `--update`. `scripts/install.sh --help` lists every option. If you already run v7.x or older, read the Migration Guide below first (M-8 and M-9 matter most).

Set the MCP environment variables named in the generated MCP config, then run
`/new-project "Your idea"` in your assistant.

## Highlights

- **MCP servers corrected and pinned (SEC-002, T638).** The `filesystem`, `git`, `github` and `supabase` launchers named packages that do not exist on npm; they now start real, exactly pinned packages. Every other `npx` server is pinned. `docker` and `postgresql` are removed.
- **`fetch` removed, `playwright` hardened (SEC-T646-01, T653 to T655).** A redirect test showed the pinned `mcp-fetch-server` requests a redirect target before rejecting it. The server is gone and agents read pages with the platform `web` tool. The `playwright` entry now runs headless, isolated, sandboxed and with an origin block list, and needs a browser installed once.
- **Installer refuses symlinks at managed paths (SEC-001, T636)** and no longer deletes client-owned files on `--update` (T518); new `--projections-only` mode (T550).
- **New `poc-security-audit` MCP server and a PoC security reviewer that blocks (T603 to T612).** It scans for secrets and checks ref containment with fixed commands and fail-closed results.
- **Gate rules tightened.** A security finding graded `SECURITY:CRITICAL` or `SECURITY:HIGH` is never a `CONDITIONAL_PASS`; a `SECURITY:MEDIUM` finding is fixed before a release ships (ADR-008, ADR-009).
- **MCP tool names are rendered per platform; Playwright grants are narrowed (T657, T658).** On GitHub Copilot the agents' MCP grants take effect for the first time. Opencode and Gemini CLI deny six unsafe Playwright tools server-wide. See Known Issues K-15 and K-16 for where this is not in force.
- **One release document and a develop-first release order (T632, T639, T640).** This file is the GitLab Release body; the commit list goes to `CHANGELOG.md` only.
- **Maturity.** 27 of 28 agents are `stable`; `tech-lead` was promoted in this release (T630); `orchestrator` is still `experimental`. New experimental skill `gitlab-api-push-fallback` (T627).

## Breaking changes

Counting rule (decision D-2, release manager, per `docs/artifacts/release-documents-ruling-v1.md` RD-5): this section lists every inventory entry that `docs/artifacts/release-v8-audit-v2.md` §1.3 marks `breaking = yes` (17 entries: A-01 to A-08, A-10, A-12, A-14, A-16, A-19, A-21, A-22, A-23, A-24) and the three entries A-25 to A-27 that the release manager added after that audit from the T653 to T658 artifacts. The count in the verdict block equals the entries listed here: 20. Four entries the audit marks `unclear` (A-13, A-15, A-18, A-20) change behaviour without a demonstrated incompatibility; they are not counted and appear in the Migration Guide only (M-2, M-4, M-5, M-7). Entries marked "maintainers" affect people who work inside the source repository, not adopters.

- **A-01** `poc-security-engineer` loses `execute` and gains three MCP tools (`mcp__security-audit__grep_content`, `mcp__poc-security-audit__scan_secrets`, `mcp__poc-security-audit__ref_containment`). It needs the new server, its dependency and a client permission (M-2, M-3).
- **A-02** New MCP server `poc-security-audit` (extended; `python3 -m implementation.runtime.security.poc_audit_server --allowed-root .`). Needs `mcp==2.2.0`, `git >= 2.40` and a launch directory equal to the project root.
- **A-03** Claude Code needs the allow rule `mcp__poc-security-audit__*` in `.claude/settings.json`, which the installer never writes (M-2).
- **A-04** GitHub Copilot cannot run the PoC security scan: the extended servers are not emitted to `.vscode/mcp.json`, and the agent treats an incomplete scan as `FAIL` (K-3).
- **A-05** The PoC security reviewer blocks on any Immutable Security Constraint breach, any omitted or weakened required control, and any `SECURITY:CRITICAL` or `SECURITY:HIGH` finding; a blocking finding is never recorded as debt.
- **A-06** Gate semantics: `CONDITIONAL_PASS` permits a merge with tracked conditions; a `SECURITY:CRITICAL` or `SECURITY:HIGH` finding, a constraint breach or an omitted control never yields it; `/security-audit` fails on `CRITICAL` or `HIGH`; `release-manager` refuses a release with an unresolved `CRITICAL`, `HIGH` or `MEDIUM` security finding (M-6).
- **A-07** Review verdicts are `PASS`, `CONDITIONAL_PASS`, `FAIL` (were `Approved`, `Changes Requested`, `Needs Discussion`); the release verdict lives in the release document.
- **A-08** PoC vocabulary: `INCONCLUSIVE` removed; debt severity is `critical`, `medium`, `low` and effort `S`, `M`, `L`; `TECHNICAL-DEBT.md` is required.
- **A-10** (maintainers) `install.sh` modes: `--projections-only` is the only mode allowed at the repository root; `--update` and any `--target` inside the source repository are refused.
- **A-12** Handoff JSON is validated more strictly: `constraints.writablePaths` must be non-empty, entries non-empty strings, at most 128 per list.
- **A-14** File naming conventions change for new files: `plan-<ID>.md`, `checkpoint-<SEQ>-<phase>.md`, `ADR-<NNN>-<slug>.md`, `<name>-v<N>.md`, `docs/releases/v<VERSION>.md`, `agent/<agent-name>/<task-id>` (M-5).
- **A-16** The orchestrator opens a branch and a merge request for every change, docs and ledger edits included.
- **A-19** `/batch` manifests live in the plan document and every unit is a real `T<NNN>` ledger row; old manifest rows are rejected.
- **A-21** (maintainers) Every command needs an `audience` key (`authoring`, `target` or `both`).
- **A-22** The extended MCP launchers are replaced and every `npx` entry is pinned (`filesystem`, `git`, `github`, `supabase` change; `docker`, `postgresql` removed). New prerequisites: `uv`, a Docker daemon, and the tokens `GITHUB_PERSONAL_ACCESS_TOKEN` and `SUPABASE_ACCESS_TOKEN` (M-8).
- **A-23** The installer and the three merge scripts refuse any symlink at a managed path or at one of its parents, even one that points inside your project (M-1).
- **A-24** (maintainers) New release procedure: `release/*` to `develop`, then to `main`, both as merge commits without squash, then the tag; the release document has the title plus 10 sections; the release job publishes it whole.
- **A-25** (added after the audit) The `fetch` server is removed and the `playwright` entry is rewritten: headless, isolated, sandboxed, service workers blocked, with a `--blocked-origins` list that blocks local-app URLs (`localhost`, `127.*`, `10.*`, `192.168.*`, `172.16-31`); it needs Chrome for Testing installed once (M-8). T653 to T655, T656.
- **A-26** (added after the audit) Agent MCP tool lines are rendered in each platform's own form (Copilot `server/tool`, Opencode `server_tool`, Pi `mcp__server__tool` with `_` for non-alphanumerics), and `qa-engineer`, `frontend-developer`, `poc-qa-engineer` and `demo-agent` hold named Playwright tools instead of the whole server. Effects on Copilot, Opencode and Pi are in M-8. T657.
- **A-27** (added after the audit) On Opencode and Gemini CLI the generated config denies six Playwright tools server-wide (`browser_run_code_unsafe`, `browser_evaluate`, `browser_file_upload`, `browser_drag`, `browser_drop`, `browser_network_request`); `install.sh --update` merges your own `permission` and `excludeTools` entries and puts the denial back. T658.

## Migration Guide

**Migration from v7.0.1 to v8.0.0.** v8.0.0 changes what some agents may do, adds one MCP server, replaces and pins the extended MCP servers, removes the `fetch` server, hardens `playwright`, tightens gate and PoC rules, makes the installer refuse symlinked managed paths and renames several file conventions. The installer renames or deletes nothing in your project except the platform trees it owns. Do the steps in this order. Everything marked **(not re-run)** was taken from a repository document and not re-run by the release manager.

**M-1. Update the installer and run `--update` once per project.**
```bash
git -C <emage.code clone> pull        # or check out the v8.0.0 tag
scripts/install.sh --target <your-project> --platform <name>|all --update
```
`<name>` is one of `cursor`, `github`, `gemini`, `opencode`, `pi`, `claude-code`, `cline`.
- `--update` replaces each platform tree it owns (`.claude/`, `.github/`, `.cursor/`, `.gemini/`, `.opencode/`, `.pi/`, `.cline/`, `.clinerules/`) and re-renders `AGENTS.md` and `CLAUDE.md`. Hand-written files inside those trees are deleted; put project-specific content in `docs/`.
- It no longer touches `.claude/settings.json`, `.claude/settings.local.json`, or `.github/{workflows, ISSUE_TEMPLATE, PULL_REQUEST_TEMPLATE*, CODEOWNERS, dependabot.y*ml, FUNDING.yml, copilot-instructions.md}`. If an earlier `--update` removed any of them, restore them from version control.
- **The installer now refuses to write through a symlink.** If any managed path, or a parent of one (`.claude`, `docs`, `implementation`, `implementation/runtime`, `.vscode`, `.mcp.json`, `CLAUDE.md`, a task ledger, and others), is a symbolic link, even one that points inside your project, the run stops with exit 1 before anything is written. Replace the link with a real file or directory, or point the installer at the real path (for example, `CLAUDE.md` as a link to `AGENTS.md` must become a real file). Do not run the installer as root into a directory other users can write to.
- MCP configs (`.mcp.json`, `.vscode/mcp.json`, `.cursor/mcp.json`, `.gemini/settings.json`, `.opencode/opencode.json`, `.pi/mcp.json`, `.cline/mcp.json`) are merged: generated values win, your extra servers and keys are kept. See M-8 for the changed entries.
- Both task ledgers are rewritten: your prose is kept, rows that are not `T<NNN>` are dropped with a warning, line endings become LF.
- New runtime files appear under `implementation/runtime/security/` (three) and `implementation/runtime/handoff/` (new directory).
- Maintainers of the emage.code checkout: `--update` and any `--target` inside the repository are refused; use `scripts/install.sh --target . --platform all --projections-only` (refreshes the platform trees, MCP configs, `AGENTS.md` and `CLAUDE.md`; never touches `docs/` or `implementation/`).

**M-2. Client settings (the installer never writes them).**
- Claude Code: add `"mcp__poc-security-audit__*"` to `permissions.allow` in `.claude/settings.json`. If you use `@security-engineer` or `@context-retriever`, the same pattern applies to `"mcp__security-audit__*"` and `"mcp__context-retriever__*"`. On first start approve the project-scoped servers when Claude Code prompts; it prompts again for the changed entries of M-8.
- Claude Code `.mcp.json` uses `${VAR}`, not `${env:VAR}` (audit entry A-13, not counted above). Export the variables for the servers you use in the environment that starts the client: `HINDSIGHT_MCP_URL`, `CWSO_MCP_URL`, `CWSO_BEARER_TOKEN`, `CWSO_ORIGIN`, `GITLAB_PERSONAL_ACCESS_TOKEN`, `GITLAB_API_URL`, `BRAVE_API_KEY`, `TOOLRADAR_API_KEY`, and, new in v8.0.0, `GITHUB_PERSONAL_ACCESS_TOKEN` (`github`) and `SUPABASE_ACCESS_TOKEN` (`supabase`). An unset variable is reported by `claude mcp list` and the literal `${VAR}` text is used; an unset token stops only that server.
- Other platforms: grant the platform's equivalent permission for `poc-security-audit` if it asks for one. **GitHub Copilot:** the extended servers are not emitted to `.vscode/mcp.json`, so the PoC security scan cannot run there (K-3).

**M-3. Dependencies.**
- Python package `mcp==2.2.0`: `python3 -m venv .venv-mcp && source .venv-mcp/bin/activate && pip install -r implementation/runtime/security/requirements-mcp-server.txt` (the installer prints this). The MCP client must start `python3` from that environment, from the project root (the server runs with `--allowed-root .`).
- `git >= 2.40` on `PATH` for `poc-security-audit` (older git: every call fails closed as `git_failed`). A POSIX host is assumed (Windows not verified).
- For the extended MCP servers (M-8): Node.js with `npx` for the `npx` servers, `uv` (`uvx`) for `git`, and a running Docker daemon that can pull from `ghcr.io` for `github`.
- For the core `playwright` server: a browser, installed once (M-8). `@context-retriever` still needs its one-time index build (unchanged since v7.0.1).

**M-4. Project files `--update` will not refresh (audit entry A-20, not counted above).** `docs/tasks/validate-tasks.py`, `docs/tasks/_template.md` and `docs/plans/_template.md` are copied only when missing. To adopt the new validator (checks C11 `**Affects:**` on P0/P1 briefs, C12 existing `Depends on` IDs, C13 no self-dependency, C14 no cycles), the `Affects` field and the `plan-<ID>` plan template, delete the old copies and re-run `--update`, or copy them from `implementation/docs/`.

**M-5. Renamed conventions.** Existing files are not renamed; new files follow the new forms.

**M-6. Severity, verdict and status vocabulary.**

| Scale | Before | Now |
|---|---|---|
| Review / gate verdict (Tech Lead, code-review) | `Approved \| Changes Requested \| Needs Discussion` | `PASS \| CONDITIONAL_PASS \| FAIL` |
| `CONDITIONAL_PASS` | merge blocked until conditions resolved (Tech Lead) | merge permitted with tracked conditions; closed before the next gate (production), carried to the next release cycle at the Release gate, recorded as debt (PoC). Never for a security finding graded `SECURITY:CRITICAL`/`HIGH`, an Immutable Constraint breach, or an omitted/weakened required control |
| Security | `/security-audit`: FAIL only on CRITICAL | FAIL on CRITICAL or HIGH, constraint breach, omitted/weakened required control; MEDIUM needs a remediation plan before merge and is fixed before a release ships |
| Blocker severity | `critical \| high \| medium \| low` | `critical \| major \| minor` (`AGENTS.md` Blocker Protocol) |
| PoC debt severity / effort | `critical/high/medium/low`; `XS..XL` | `critical/medium/low`; `S/M/L` |
| PoC verdict | `Validated \| Invalidated \| Inconclusive` | `Validated \| Invalidated` (weak or untested evidence is `Invalidated` with `Evidence strength: weak`); progress report `verdict=in_progress` only at a milestone |
| Task status values in skill examples | `in-progress`, `review` | `in_progress`, `in_review` (as `AGENTS.md`) |
| Task fields in skill examples | `Assignee`, `BlockedBy`/`Blocks`, `high/medium/low`, `must/should/could` | `Owner`, `Depends on` (blocks are derived), `P0/P1/P2` |
| GitLab `priority::` label to ledger priority | no mapping in the skill | `priority::critical` and `high` agree with `P0`, `medium` with `P1`, `low` with `P2` (`gitlab-management`); the mapping does not reverse |

`/bug-report` still uses its own four-level bug severity and maps it to `P0/P1/P2`.

**M-7. Behaviour changes to brief your team on.**
- The orchestrator opens a branch and a merge request for every change, docs and ledger edits included.
- Only orchestrators write `active-tasks.md`; the Scrum Master and skills propose rows (audit entry A-15, not counted above).
- `/consolidate-memory` writes to project-owned `docs/` files, never to `AGENTS.md`/`CLAUDE.md`/platform folders, and keeps a memory entry until the write is re-read.
- The PoC security reviewer blocks the PoC on critical/high findings, exposed secrets, constraint breaches and omitted controls; it cannot be waived or recorded as debt. Placeholder flags are created only by the user.
- The PoC debt scan covers every text file under the PoC root (skipping `.git`, `node_modules` and the debt registers).
- Handoff JSON: `constraints.writablePaths` must list at least one path; entries must be non-empty strings; at most 128 per list.
- Command authors in the source repository: every command needs `audience: authoring | target | both`.
- **Maturity.** `tech-lead` is now `stable` (T630); `orchestrator` is the only agent still `experimental`. Maturity is not projected into installed files, so installed agents are unchanged by this. A new experimental skill, `gitlab-api-push-fallback`, is installed (T627).

**M-8. MCP changes (SEC-002, SEC-T646-01, T655 to T658).** After `--update`:

| `supabase` | `npx -y @supabase/mcp` (does not exist) | `npx -y @supabase/mcp-server-supabase@0.13.0 --read-only` | `SUPABASE_ACCESS_TOKEN` in the environment |

| `playwright` | `npx -y @playwright/mcp@latest` | hardened, `@playwright/mcp@0.0.83` (below) | a browser, installed once |

- `filesystem`, `git`, `github`, `supabase` and `playwright` are overwritten in place; a key you added inside one of those entries is kept (except the generator-owned `args` of `playwright`, which `--update` restores). Your own entries with other names are kept.
- **The `extended` servers reach every platform except GitHub Copilot.** `filesystem` (the whole project directory, including `.env*` and `.git`), `git` (with write tools), the `github` container, `supabase` (`--read-only`), `toolradar`, the remote `cwso` and `hf-mcp-server`, and the local `context-retriever`, `security-audit` and `poc-security-audit` are written into the generated config of Claude Code, Cursor, Gemini CLI, Opencode, Pi and Cline (`implementation/knowledge/mcp/servers.yaml`, tag `extended`); the Copilot `.vscode/mcp.json` holds only core servers. Before this release the launchers of `filesystem`, `git`, `github` and `supabase` named packages that do not exist, so those four failed to start; they now start real, pinned packages, so the capabilities above can run for the first time in any session that approves the server (`github` and `supabase` also need their tokens). `toolradar` already started in v7.0.1 and is now pinned.
- **Removing `docker`, `postgresql` and `fetch`.** They are removed automatically only if the installed file's `<file>.provenance.json` sidecar lists them as generator-owned (in a scratch test of an upgrade from a v7.0.1 install, all three were removed). If the install has no sidecar, or the sidecar no longer lists them, remove the server objects from every installed MCP config by hand (Cline's real configuration is global), or run once per file **and once per name**: `python3 scripts/merge-mcp-json.py --source <generated file> --dest <your file> --force-prune-keys fetch`, then the same with `docker` and `postgresql`. `<generated file>` is the file of your clone of the emage.code repository that matches your platform: `implementation/.mcp.json` for Claude Code (installed as `.mcp.json`), `implementation/.vscode/mcp.json` (GitHub Copilot), `implementation/.cursor/mcp.json`, `implementation/.gemini/settings.json`, `implementation/.opencode/opencode.json`, `implementation/.pi/mcp.json` and `implementation/.cline/mcp.json`; `<your file>` is the installed file of the same platform (`.vscode/mcp.json`, `.cursor/mcp.json`, `.gemini/settings.json`, `.opencode/opencode.json`, `.pi/mcp.json`, `.cline/mcp.json`; Cline's global file too). A name that is not present in a given file is refused by `--force-prune-keys` with exit 1 and writes nothing (for example `docker` and `postgresql` on the Copilot `.vscode/mcp.json`, which holds only core servers): skip it. The combined form `--force-prune-keys docker,postgresql,fetch` refuses and writes nothing if any one name is already gone from that file **(not re-run)**. `install.sh` does not pass this option. An entry of your own named `docker`, `postgresql` or `fetch` is removed too when the old sidecar lists those names; re-add it under another name. Agents no longer list `mcp__fetch`; they read pages with the platform `web` tool.
- **Playwright prerequisite.** The server does not bundle or download a browser. Install it once with the command pinned to the server version: `npx -y @playwright/mcp@0.0.83 install-browser chrome-for-testing` (about 670 MB; Chrome for Testing 155.0.8059.12, revision 1247). The entry sets `--browser chromium`, `--sandbox` (which can fail in containers and on hosts that block unprivileged user namespaces, unverified there), `--headless`, `--isolated`, `--block-service-workers` and `--no-webmcp`. The browser is patched only when the pin is bumped. Add `.playwright-mcp/` to your project's `.gitignore`: page snapshots and downloads are written there and `install.sh` does not edit your `.gitignore`. `install.sh` also does not print the browser step or this `.gitignore` advice; they are in `implementation/PREREQUISITES.md` and here. Details: https://gitlab.com/em-age/emage.code/-/blob/main/implementation/PREREQUISITES.md
- **Local apps are blocked by the shipped `playwright` entry.** Its `--blocked-origins` list denies loopback, private, link-local and carrier-grade-NAT ranges, so a call to `http://localhost:3000` fails with `net::ERR_BLOCKED_BY_CLIENT`. To test a local app, add a second entry of your own named `playwright-local` (the same arguments without `--blocked-origins`; the exact entry is in `implementation/PREREQUISITES.md`). It is kept by `--update`. It has no origin restriction and is not covered by the denials below: use it only on a development machine, for your own pages, and remove it when you are done. Do not edit the arguments of `playwright` itself.
- **Per-platform tool names (T657).** Agent sources keep one form, `mcp__<server>__<tool>`; the generator renders each platform's documented form: GitHub Copilot `server/tool` and `server/*`, Opencode `server_tool` and `server_*`, Pi `mcp__server__tool` with every character other than letters, digits and `_` replaced by `_` (`security-audit` becomes `security_audit`) and `__*` for a whole server; Claude Code is unchanged; Gemini CLI drops the tools line; Cursor and Cline render no agent MCP list. What changes for you: on **GitHub Copilot** the old `mcp__...` tokens were not recognised and granted nothing, so the MCP grants of 14 agents (`gitlab`, `memory`, `sequential-thinking`, `playwright`, `security-audit`) take effect **for the first time**; on **Opencode** the entries are written as `x: true`, which sets `allow` and, per the documentation, overrides your own `ask` or `deny` for those tools; on **Pi** the lists are honoured only for agents that list an `mcp__` tool and only if your agent runner passes the list to `pi --tools`. ## Rollback Plan

**Tested once, on a scratch project, for the adopter side; not tested for the maintainer side or for a real project.** The test (release manager, 2026-10-15): a scratch git repository was installed with the v7.0.1 installer (`--platform all`), given a `.claude/settings.json` and a `.github/workflows/ci.yml`, upgraded with this release's `scripts/install.sh --update`, and then rolled back by running the v7.0.1 installer (taken from the `v7.0.1` tag with `git archive`) with `--update` on the same project. Exit code 0 each time. Steps and what the test showed:

1. Commit or back up `.claude/settings.json`, `.github/workflows/` and any other project-local file first. **The v7.0.1 `--update` deleted both** in the test (it does not spare client-owned files; that was fixed in v8.0.0). Restore them from version control afterwards.
2. Check out the `v7.0.1` tag of the installer clone and run `scripts/install.sh --target <your-project> --platform <name>|all --update`.
3. **The MCP configs are merged back to the v7.0.1 entries, which restores the four nonexistent launchers** (`@anthropic/mcp-filesystem`, `@github/mcp-github`, `@modelcontextprotocol/mcp-git`, `@supabase/mcp`), the unpinned servers (including `mcp-fetch-server` without a version), `docker` and `postgresql`, and `playwright` as `@playwright/mcp@latest` without the hardening. Remove or replace the `filesystem` entry again as in M-9, and consider removing the other three.
4. Corrections to the earlier draft of this plan: the three v8 files under `implementation/runtime/security/` (`git_executor.py`, `poc_audit_server.py`, `poc_scan.py`) are **deleted**, not left behind; the `poc-security-audit` server entry is removed from the MCP configs; the `gitlab-api-push-fallback` skill is removed from every platform tree. `implementation/runtime/handoff/` stays.
5. The Opencode `permission` denial and the Gemini `excludeTools` list stay in the merged files in the test (harmless: they only deny tools); remove them by hand if wanted. The Claude Code allow rule you added is lost with `.claude/settings.json` unless you restore it.
6. A rollback does not undo a symlink you replaced for M-1 and does not restore files you removed by hand.

Not tested: a real project, Windows, Cline's global MCP file, an install without a provenance sidecar, a platform subset, and a rollback after a partial `--update` failure.

Maintainers of the source repository: a published release is never undone by deleting or moving its tag. If a defect is found after the tag, fix it forward with a hotfix branch from `main` and a patch release (`v8.0.1`), merged to `main` and `develop`.
