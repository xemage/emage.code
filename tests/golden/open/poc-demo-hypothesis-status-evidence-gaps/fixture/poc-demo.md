# PoC Demo Package: Local full-text note search

Audience: platform team leads (30 minutes). Outcome to prove: FTS5 is fast enough to drop the
planned search service from the v1 design.

## Demo Walkthrough Script
1. Open the terminal with the pre-built `notes.db` (200,000 synthetic notes).
2. Run `replay --workload prefix-1000 --runs 1` and narrate the live latency histogram.
3. Type a query in the toy search box and show results updating per keystroke.
4. Show the index file size next to the raw corpus size.

## Sample Data and Input Sequence
- Corpus: 200,000 notes generated by the PoC's seeded generator (seed 7); all names, addresses and
  text are synthetic — no real user data.
- Input sequence: the fixed `prefix-1000` workload (1,000 prefix queries, replayed in file order),
  then the live queries `meet`, `meeting n`, `meeting notes q3`.

## Expected Visible Outcomes
- Histogram p95 marker below the 50 ms line on the replayed workload.
- Results visibly update on every keystroke in the toy search box.
- Index size shown at roughly 1.4x the raw corpus.

## Presenter Notes and Fallback Path
- Notes: stress that only one of the three required runs has completed (see Hypothesis Status).
- Fallback: if the live replay stalls, play the recorded run (`demo/run-1.cast`) and say so.

## PoC-Only Shortcuts Shown in the Demo
- The search box is a throwaway terminal UI, not the product UI.
- The corpus is synthetic; its term distribution is assumed, not measured against real notes.
- No concurrent writers: the index is built once and read-only during the demo.

## Production Transition Notes
- Concurrent write load is untested; production needs a writer-under-load benchmark before adoption.
- The throwaway UI and seeded generator are not production artifacts and must not be carried over.

## Mocked / Simulated vs. Real
| Demo element | Real or mocked/simulated |

| FTS5 index and query engine | Real |

## Hypothesis Status

- **Hypothesis**: SQLite FTS5 can serve ranked search-as-you-type over a 200,000-note corpus on a
  developer laptop with p95 < 50 ms, without a separate search service.
- **Validation status**: IN_PROGRESS
- **Key evidence demonstrated**:
  - Run 1 of 3 of the replayed `prefix-1000` workload, p95 shown live
  - Index build time on the demo laptop
- **Evidence gaps**:
  - Runs 2 and 3 have not completed; the success criteria require 3 consecutive runs
  - Behaviour under concurrent writes is not demonstrated at all
  - The synthetic corpus's term distribution is not validated against real notes
- **Confidence level**: MEDIUM

Directly validating parts: walkthrough steps 2 and 4 (latency and index size). Steps 1 and 3 are
context only.
