## Highlights

**CWSO agent knowledge awareness** (T327–T330): CWSO (Concurrent Workspace Orchestration) has
been deployed and runtime-validated since earlier releases, but no emage.code agent actually knew
it existed. This release closes that gap.

- Added `implementation/knowledge/skills/cwso-awareness/SKILL.md` — explains what CWSO/Pattern A
  is, the mandatory `worker`/`orchestrator` role split enforced by the live server (violating it
  produces an HTTP 403), and the approved agent-to-permission-tier mapping.
- Wired a "CWSO Awareness" section into the `orchestrator`, `backend-developer`, and
  `devops-engineer` agent knowledge files, stating each agent's CWSO permission tier.
- Propagated the new skill to all six platform projections (`.claude`, `.github`, `.cursor`,
  `.gemini`, `.opencode`, `.pi`) via `make sync` plus a full `scripts/install.sh --update`.
- Independently gated: a solution-architect review confirmed the embedded role-mapping table is
  byte-for-byte identical to the source artifact (`docs/artifacts/role-mapping-cwso-v1.md`), with
  no invented tiers.
- Added `docs/deployment/cwso-overview-and-agent-integration-guide.md` — a single narrative guide
  from "what is CWSO and why" through deployment and runtime usage to agent-knowledge wiring.

**Local CWSO deployment and connection fixes**:

- `scripts/deploy/cwso-docker-desktop.sh`: fixed no-arg invocation (previously failed with
  `Unknown option: setup` instead of entering the setup flow); help text now points to the correct
  `/healthz` liveness endpoint.
- `docs/deployment/local-docker-desktop-guide.md`: removed stale manual `docker-compose`/
  `deploy/local-dev` workflow references, aligned end to end with
  `docker compose -f deploy/docker-compose-t226.yml`.
- Added a working `.vscode/mcp.json` entry for the `cwso` MCP server (HTTP transport, bearer token
  via a `promptString` input) and `scripts/mint-cwso-jwt.py`, which mints HS256 tokens with the
  `exp`/`role`/`sub` claims CWSO's orchestrator actually requires — fixing the "missing required
  claim: exp" rejection produced by hand-rolled tokens.
- Added `docs/deployment/cwso-emage-orchestrator-connection-guide.md`, tested end to end against a
  live stack, and linked it from `docs/deployment/README.md`.
- `deploy/local-dev/` (a runtime-generated working copy of `docker-compose-t226.yml`/
  `t226-phase2.env`, including the JWT secret reference) is now correctly `.gitignore`d — it was
  never meant to be source-controlled.
