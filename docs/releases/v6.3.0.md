## Highlights

**Plan 014 — Task Ledger Hardening** (T242–T284): a full audit and repair of the
task-ledger tooling shipped to target projects, closing 18 defects (D1–D18)
identified in the ledger contract, the `install.sh --update` pipeline, and the
repo's own historical task data.

- **Shipped ledger validator** (T256, T258–T260): a new `docs/tasks/validate-tasks.py`
  is now installed into every target project, plus a `/validate-tasks` command
  and a task brief template (`docs/tasks/_template.md`). Checkpoints and release
  preparation now require the validator to pass before proceeding.
- **Task lifecycle and schema fixes** (T244–T254, T257, T262–T263): corrected the
  active/completed ledger column schema (7 columns / 5 columns), added the
  `cancelled` lifecycle state, made archival orchestrator-only, fixed
  `sprint-status`/`team-status` to read both ledgers, widened the task-ID row
  regex to tolerate `T<NNN+>` IDs and loose spacing, and made `merge-task-docs.py`
  warn (instead of silently dropping) on non-conforming rows such as `BUG-`
  prefixed IDs.
- **`install.sh --update` safety** (T265): the updater now warns before it
  replaces `.github`/`.cursor`/`.gemini`/`.opencode`/`.pi` wholesale via
  `rsync --delete`, so local platform-folder edits are not silently lost.
- **Registry check wired into every gate** (T276–T281): `make verify` only
  checks projection drift, not the knowledge registry — Gates 1–3, the plan's
  FINAL GATE, and the executable `task-T275.md` FINAL GATE brief now all run
  `check.py --registry` explicitly, closing a blind spot that let the registry
  go stale for three prior waves without detection.
- **Repository ledger data repaired** (T268–T272, T282–T284): resolved the
  orphaned `T214`/`T037` task-ID gaps, re-sorted `completed-tasks.md` by
  completion date, consolidated four inconsistently-named brief files
  (`brief-T202.md`, `brief-T210.md`, `brief-T211.md`, `task-T220-CONDITIONS.md`)
  into their canonical `task-T<ID>.md` files, and fixed a regression in
  `tests/performance/test_team_health.py` where a warning block had been
  misplaced across two test classes during earlier hardening work.
- **Terminology sweep** (T273–T274): replaced every stale `TASK-NNN` reference
  with the canonical `T<NNN>` ID format across 13 knowledge files, and aligned
  the technical-debt-tracking skill's priority vocabulary (`P0`/`P1`/`P2`)
  with the rest of the knowledge base.
- **Historical ledger compliance**: generated missing brief stubs for
  long-completed tasks (`T022`, `T023`, `T046`–`T054`) and normalized
  `**Status:**` headers across ~62 historical briefs so the shipped validator
  reports a clean `TASK LEDGER: PASS` for the repository's own 123 completed
  tasks.
