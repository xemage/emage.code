## Highlights

### Fixed

- **Remote MCP server transport encoding corrected for Cline, VS Code/GitHub Copilot, and Gemini
  CLI** (T360-T365, plan-030-mcp-remote-transport-alignment): a real runtime failure surfaced that
  Cline's generated MCP config for the two hosted/remote servers (`context7`, `hf-mcp-server`) used
  a transport identifier Cline doesn't recognize. Rather than assume that one fix generalized, this
  release runs a documentation-backed audit of every platform's own current official MCP config
  schema before changing anything:
  - **Cline** — was `"type": "http"` (not a recognized Cline transport value; Cline silently falls
    back to the deprecated `sse` transport instead of failing loudly). Corrected to
    `"type": "streamableHttp"`.
  - **VS Code / GitHub Copilot** — was missing the `"type"` field entirely, which VS Code's own MCP
    schema requires for HTTP/SSE servers. Added `"type": "http"`.
  - **Gemini CLI** — was using the `"url"` key, which Gemini CLI reserves for the legacy SSE
    transport. Corrected to `"httpUrl"`, the field Gemini CLI documents for streamable-HTTP remotes.
  - **Cursor, Opencode, and Claude Code were audited and confirmed already correct — no change.**
    This release's own plan initially assumed Claude Code shared Cline's staleness; the completed
    audit disproved that assumption before any generator branch was touched (see
    `docs/tasks/task-T360.md` for the full per-platform evidence table).
  - **Pi** is flagged as an explicitly disclosed open item: no independently-confirmed official Pi
    MCP documentation could be located, so Pi's remote-server shape (inherited verbatim from
    Cursor's generator branch) is not independently verified either way.
  - New regression test coverage (`tests/functional/test_platform_projections.py`) now asserts the
    exact per-platform transport shape for every platform that emits a remote MCP server, closing
    the gap that let this drift ship undetected until it surfaced as a real runtime failure.
  - See `docs/wiki/mcp-servers.md` § "Remote-server transport encoding differs per platform" for
    the full per-platform reference table.

  **Action needed:** regenerate your local platform configs — `make sync`, or reinstall via
  `scripts/install.sh --target <dir> --platform <platform> --update` — to pick up the fix.

## Breaking changes

- None. This release only corrects generated output for the two hosted remote MCP servers
  (`context7`, `hf-mcp-server`) on the three platforms named above; no stdio server entry, API
  contract, or platform manifest schema changed. Confirmed via `implementation/scripts/sync.mjs
  --check` (0 drift across all 7 platforms after regeneration) and the full test suite (294 tests,
  0 failures).
