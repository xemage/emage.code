## Highlights

Patch release. No new features. Two housekeeping items plus one real bug fix
found while self-installing the emage.code repository onto itself:

- **Claude Code platform installed into this repository**: `.claude/` (27
  agents, 19 skills, 19 commands, 4 rules), `.mcp.json`, and `CLAUDE.md` are
  now tracked here, completing the platform's own self-hosting after it
  shipped for external projects in v6.4.0.
- **Plan 014 approval paperwork closed**: `docs/plans/plan-014-task-ledger-hardening.md`
  had already been fully executed (T242–T284, released as part of v6.3.0) but
  its own Status/Approval header was never updated. Re-verified all 18
  defects, the full test suite, `make verify`, the registry checker, and a
  fresh-install-then-`--update` round trip — all pass — and recorded the
  approval and gate evidence.
- **Fix: `scripts/merge-task-docs.py` now backfills non-`.md` support files
  during `--update`**. The `--update` sync previously only globbed
  `docs/tasks/*.md`, so a target whose `docs/tasks/` predates a new support
  file (like `validate-tasks.py`, shipped by plan-014) never received it —
  only a *fresh* install did. This repository's own `docs/tasks/` had never
  been through a fresh install and was missing `validate-tasks.py` as a
  result; the generalized sync now seeds any missing template-dir file
  (directories such as `__pycache__` are still skipped), proven against this
  repo's own ledger.
