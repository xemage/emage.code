## Highlights

Patch release focused on deployment correctness and reproducibility for the CWSO-backed local stack.

- Switched `deploy/docker-compose-t226.yml` from local source builds to published CWSO registry
  images (`orchestrator`, `git-shadow`, `merge-engine`, `rollout`) pinned at `v0.5.2`.
- Added `deploy/docker-compose-t226.build.yml` as an opt-in local source build override using
  `CWSO_SOURCE_DIR` (default `../CWSO`) to preserve contributor workflows without hardcoded
  machine-specific paths.
- Updated `scripts/deploy/cwso-docker-desktop.sh` update/status/log paths to operate against
  `deploy/docker-compose-t226.yml` and fixed health checks to use the correct unauthenticated
  liveness endpoints (`/healthz`).
- Updated deployment documentation and task evidence for the full Plan-017 Wave 5 closure,
  including verified pull-based bring-up and healthy runtime state.

## Breaking changes

None for public APIs.

Operational note: default local deployment now pulls from the public CWSO registry rather than
building from a sibling checkout. Developers who need source-build behavior should use:

```bash
docker compose -f deploy/docker-compose-t226.yml -f deploy/docker-compose-t226.build.yml up -d --build
```
