## Highlights

**Main/develop drift detection** (plan-019, T332–T336): a new CI capability that continuously
verifies `main` and `develop` stay in sync, preventing the kind of silent GitFlow divergence
diagnosed and remediated in T331 (see "Internal" below) from recurring.

- Added `scripts/check-main-develop-drift.py` — compares the `Latest release: vX.Y.Z` README
  marker across `origin/main` and `origin/develop`, and computes how many releases (by tag index)
  `main` is behind `develop`, allowing a 1-release grace window before flagging drift. Live run
  against this repo's real state confirmed `main=v6.5.0 develop=v6.5.0 releases_behind=0`,
  `MAIN-DEVELOP DRIFT: PASS`, exit 0 (T332).
- Added regression tests for the script's pure functions (`parse_marker`, `semver_key`,
  `sorted_valid_tags`, `releases_behind`, `evaluate`) — `tests/functional/test_check_main_develop_drift.py`,
  16 tests, isolated run `OK` (T333). Note: T333's own task brief narrative said "14 total" tests,
  but its exact-content code block defines 16 — this is a documented brief-text discrepancy, not a
  code defect (see T333/T336 evidence), and is called out here for traceability rather than
  silently rounded off.
- Wired the check into `.gitlab-ci.yml` as two new jobs (T334):
  - `main-develop-drift-check` — `verify` stage, non-blocking (`allow_failure: true`), runs on
    every push to `develop`.
  - `main-develop-drift-gate` — `release` stage, blocking, runs on tag pushes matching the release
    tag pattern; wired into the `release` job's `needs:` so a release cannot publish while `main`
    and `develop` have drifted beyond the grace window.
- Documented the gate in `CONTRIBUTING.md` under a new "### Drift detection" subsection (grace
  window, blocking vs. informational behavior, remediation steps) (T335).
- End-to-end verification gate (T336): VERDICT **PASS** on all 5 criteria — standalone script run
  against real `origin/main`/`origin/develop` (`MAIN-DEVELOP DRIFT: PASS`, exit 0); full test suite
  286 tests exit 0 (270 baseline + T333's 16 new tests, correcting the brief's stated "14");
  `.gitlab-ci.yml` valid YAML with both new jobs wired exactly once each and `release:` `needs:`
  including the gate; `CONTRIBUTING.md` "### Drift detection" section present; `validate-tasks.py`
  → TASK LEDGER: PASS.

## Internal

- T331: GitFlow drift remediation — `main` and `develop` had genuinely diverged since v6.0.3
  (65 conflicting files on `release/v6.5.0 → main`, MR !103, merged 2026-08-07). Resolved by
  taking `develop`'s side throughout after confirming `main` held zero independent commits on any
  conflicting path; security review of the 3 affected CWSO runtime files passed (strictly
  additive). `main` verified content-identical to `develop` post-merge; post-merge pipeline green.
  This incident is the direct motivation for the plan-019 drift-detection capability shipping as
  this release's headline feature — the new CI gate exists specifically to prevent a recurrence of
  what T331 had to remediate by hand.
- Task ledger: T332–T336 archived to `docs/tasks/completed-tasks.md`.
- Full local test suite verified clean before merge: `python3 -m unittest discover -s tests -p "test_*.py"` → 286 tests, OK (per T336 evidence; re-verified independently as part of this release cycle — see the release checkpoint for this cycle's own literal run output).
