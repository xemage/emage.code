## Highlights

### Fixed

- **`--update` no longer silently overwrites hand-added entries in any of the 7 platforms' MCP /
  settings files** (T368-T372, T377-T381, plan-031 + plan-033 P033-01/02; T386-T388, plan-033
  P033-10/11 for a related cleanup below). Previously, `scripts/install.sh --update` replaced
  `.vscode/mcp.json`, `.mcp.json`, `.cursor/mcp.json`, `.gemini/settings.json`,
  `.opencode/opencode.json`, `.pi/mcp.json`, and `.cline/mcp.json` wholesale on every update,
  silently destroying any manually-added server entries, env-var inputs, or platform-specific
  sibling keys (Gemini's `hooks`, Opencode's `$schema`/`instructions`) a user had added by hand.
  The installer now merges instead of overwriting for all 7 platforms: generator-owned keys
  (`context7`, `hf-mcp-server`, etc.) always refresh to the current generated content, hand-added
  keys and top-level sibling fields survive untouched, and a fresh install remains a byte-identical
  plain copy. Verified directly against this repository's own root self-install: a hand-added
  `cwso` MCP server entry and its `inputs` block in `.vscode/mcp.json` survived a live
  `--update --platform all` run unchanged.

  **Action needed:** none for existing installs — `--update` now protects your local
  customizations by default. If you previously worked around the overwrite behavior with manual
  backups, that workaround is no longer necessary.

- **`--platform all` installs/updates omitted Cline-specific references from generated root docs**
  (T373-T376, plan-032). `scripts/render_installed_agents.py`'s `render()` function hard-coded six
  platforms' reference strings as literals when composing the `all`-platform variant of the root
  `AGENTS.md` (and any target project's generated `AGENTS.md`), omitting Cline (added as a
  supported platform in v6.8.0) from the Skill Workflow, Code Standards, Security, and MCP Servers
  sections. Rewritten to derive all five reference strings from `PLATFORM_MAP` so any future
  platform addition needs no matching code change here. New regression coverage closes the gap
  that let this ship undetected for one release cycle.

### Removed

- **`e2b`, `redis`, `figma`, and `notion` MCP server entries removed** (T386-T388, plan-033
  P033-10/11, per explicit user request — not a discovered defect). These four `extended`-tagged
  server blocks are deleted from `implementation/knowledge/mcp/servers.yaml`, every regenerated
  platform tree, and all hand-authored docs that referenced them
  (`implementation/PREREQUISITES.md`, `implementation/SECURITY.md`, `docs/wiki/mcp-servers.md`,
  both `AGENTS.md` files). This repository's own root self-install mirror files needed a
  purpose-built provenance mechanism (below) to complete the same removal safely — see Internal.

### Hardened

- **MCP/settings output hardened against secret leakage and validated where an official schema
  exists** (T383-T385, plan-033 P033-07/08/09, security follow-up). A new automated guard scans
  every generated MCP/settings output file (all 7 platforms, both canonical `implementation/`
  copies and this repository's own root self-install mirrors) for any `env` value that isn't the
  generator's own `${env:VAR}` placeholder syntax — defense-in-depth against a repeat of a
  previously-fixed live-key leak. Two platforms (Gemini CLI, Opencode) that publish an official
  JSON Schema for their config file now have their generated output validated against a vendored
  copy of that schema; the other five platforms, confirmed to have no published schema, get an
  explicit manual-verification checklist in `docs/wiki/mcp-servers.md` instead of a false sense of
  automated coverage.

## Breaking changes

- None. The `--update` merge-safety change (above) is strictly additive protection for existing
  installs — it changes destructive overwrite behavior into safe merge behavior, and no consumer
  could have depended on the old overwrite-and-lose-my-edits behavior as a feature. The new
  per-file `<mcpfile>.provenance.json` sidecars (Internal, below) are new files alongside existing
  output, not a replacement of any existing file, and the one-time `--force-prune-keys` bootstrap
  bridge used internally to complete the `e2b`/`redis`/`figma`/`notion` removal on this
  repository's own root mirrors is opt-in only — a plain `--update` run on any downstream install
  prunes nothing on its first post-upgrade run (confirmed in `docs/wiki/mcp-servers.md` § "Provenance-aware
  merge on `--update`"). No stdio server entry, API contract, or platform manifest schema changed
  for any of the 15 remaining MCP servers. Confirmed via `implementation/scripts/sync.mjs --check`
  (0 drift across all 7 platforms) and the full test suite (320 tests, 0 failures) at the time this
  release was cut.

## Internal

- **plan-031 — installer MCP JSON merge-safety, 2-platform pilot** (T368-T372): built the
  key-preserving JSON merge path (`scripts/merge-mcp-json.py`) for `.vscode/mcp.json`/`.mcp.json`
  first, with 5 new regression tests and documentation, before extending it further.
- **plan-032 — `render_installed_agents.py` Cline platform-map fix** (T373-T376): fixed the
  hard-coded `all`-platform literal-string bug described above; added regression coverage; tech
  lead implementation-gate PASS.
- **plan-033 — MCP settings hardening** (T377-T388, T383-T385):
  - T377-T381: extended the merge-safety pattern from plan-031 to all remaining 5 platforms
    (cursor, gemini, opencode, pi, cline), with 5 new per-platform regression tests and doc
    updates; tech lead implementation-gate PASS.
  - T383: added `tests/functional/test_mcp_secret_guard.py`, the literal-secret guard described
    above.
  - T384: live-researched official JSON Schema availability per platform; added schema validation
    for the 2 platforms that publish one; documented a manual checklist for the other 5.
  - T385: closed out a previously-inconclusive Pi MCP-format research question with an
    explicit, reasoned decision (Pi ships no native MCP spec; keep the Cursor-derived format
    assumption) rather than leaving it open a third time.
  - T386-T388: removed the `e2b`/`redis`/`figma`/`notion` server entries described above; tech lead
    implementation-gate PASS.
- **plan-034 — MCP merge provenance tracking** (T389-T393, T382): designed
  (`docs/decisions/ADR-002-mcp-merge-provenance-tracking.md`) and implemented a per-MCP-file
  `<mcpfile>.provenance.json` sidecar mechanism that records which JSON keys the generator itself
  owns, enabling `scripts/merge-mcp-json.py --update` to distinguish "the generator retired this
  key" from "a human added this key" — the missing piece that had left plan-033's
  `e2b`/`redis`/`figma`/`notion` removal structurally blocked on this repository's own root
  self-install mirrors since T382's first attempt. A first implementation pass against ADR-002's
  original design was found structurally broken during review (every platform nests server names
  one level inside a per-format wrapper key, never at the top level) and was corrected
  pre-merge by the solution architect before landing. 9 new regression tests cover hand-added-key
  survival, the bootstrap-absent-sidecar default, real two-generation pruning, the critical
  over-pruning guard, and the `--force-prune-keys` opt-in scoping. T382 then re-ran this
  repository's own `--update --platform all` plus the one-time `--force-prune-keys` bootstrap
  bridge and independently confirmed both proof classes: hand-added entries (the `cwso` block and
  `inputs` array in `.vscode/mcp.json`) survived byte-for-byte, and all 4 retired servers are fully
  removed from every root mirror file with zero remaining references repo-wide.
- Task ledger: T360-T393 archived to `docs/tasks/completed-tasks.md`; `active-tasks.md` returned to
  empty after this release's own task rows are closed out.
