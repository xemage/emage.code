## Highlights

### Added

- `scripts/verify-main-sync-merge.py` (T341): a post-merge squash/ancestry verification gate.
  Following T340's investigation (see "Internal" below), which independently confirmed via git
  plumbing and GitLab's own MR API records that the "phantom ancestry" commits flagged by
  T331/T339 were GitLab's own documented `squash_commit_sha` for MRs !103/!109 despite an explicit
  `squash: false` override on both merges, T341 implemented the recommended remediation: this
  script asserts `squash == false` / `squash_commit_sha == null` on a just-merged MR and exits 1 if
  GitLab squashed anyway. A regression fixture reproduces MRs !103/!109 as FAIL cases. New
  "Post-merge squash verification" subsection added to `CONTRIBUTING.md` § Releasing documents the
  usage. Independently re-verified live against the real API (both !103 and !109 correctly FAIL).

### Fixed

- **BUG-H** (T343): `ast_conflict_check.py`'s absolute import
  (`from implementation.runtime.cwso.client import ...`) changed to the relative-import style
  already used by `concurrent_merge.py`, eliminating a dual-class-identity hazard. Independently
  verified: `ast_conflict_check.CwsoClient is concurrent_merge.CwsoClient` now `True`.
- **BUG-A + BUG-F** (T344): `ConcurrentMergeOrchestrator` role-split (see "Breaking changes" below)
  plus a new collision guard — `_build_merge_inputs` now raises a clear `ValueError` (naming the
  path and contributing roles) on same-path 3+-worker collisions instead of silently dropping data.
  New regression tests cover both the role-routing and the collision guard. Independently
  re-verified: full suite (293 OK) and a live integration run against a real reachable CWSO stack
  (4/4 scenarios passed).
- **BUG-E** (T345): `write_shadow_file` now best-effort regex-extracts `blob_oid` from the live
  server's non-JSON prose response (only when still enveloped after the normal unwrap, and never
  raises on non-match), making the module's existing docstring claim true without waiting on a
  CWSO-side fix.

## Breaking changes

- **`ConcurrentMergeOrchestrator.__init__` signature change** (T344,
  `implementation/runtime/cwso/concurrent_merge.py`): changed from `(self, client)` to
  `(self, worker_client, orchestrator_client)`. Callers must now supply two role-scoped clients —
  `worker_client` for shadow-workspace lifecycle and AST precheck, `orchestrator_client` for
  `merge_concurrent_results` — instead of a single shared client. This changed because the live
  CWSO server's permission model requires role-scoped credentials for these two operation classes;
  a single shared client cannot satisfy both. A full-repo `grep` (performed during T344 and
  independently re-confirmed during T346's gate) found no caller of this constructor outside this
  repo's own tests — no external caller is known to be affected as of this release.
