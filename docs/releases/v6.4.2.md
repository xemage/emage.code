## Highlights

Patch release. One bug fix, found while using the Claude Code platform (shipped in v6.4.0)
to plan and execute work in this very repository.

- **Fix: Claude Code subagents were generated with a broken `tools:` frontmatter, leaving
  them unable to use almost any tool.** `implementation/platforms/claude-code.json` declared
  `"tools": "string"`, and `sync.mjs` copied the source `tools:` array — abstract emage.code
  categories such as `read`, `search`, `edit`, `execute`, `agent`, `web`, `todo` — verbatim
  into generated `.claude/agents/*.md` frontmatter. None of those are real Claude Code tool
  names, so the Claude Code harness granted none of them; only already-literal `mcp__*`
  entries resolved. Confirmed live: an Orchestrator subagent invocation on this platform
  could call only `mcp__memory` and `mcp__sequential-thinking` — unable to read a single
  file. Added a `toolMap` to the manifest (`read`/`search` → `Read`, `edit` → `Edit, Write`,
  `execute` → `Bash`, `agent` → `Agent`, `web` → `WebFetch, WebSearch`, `todo` → `TodoWrite`)
  and applied it in `sync.mjs` before emitting the tools string, deduplicating overlapping
  mappings. All 27 generated Claude Code subagents now carry real, usable tool grants.
- A pre-existing test (`test_claude_code_agents_use_tools_string`) had asserted the broken
  behavior as correct — it checked the projected tools string was a verbatim echo of the
  abstract source array. Strengthened it to assert the translated, deduplicated result and
  to reject any leaked abstract category name, across all 27 generated agents.

## Breaking changes

None. Only Claude Code's own generated agent frontmatter changes; no other platform's
projection is affected (verified via `make verify` — zero drift across the other five
platforms).

- `tests/functional/test_platform_projections.py`: `test_claude_code_agents_use_tools_string`
  rewritten to assert translated tool names and reject leaked abstract categories.
