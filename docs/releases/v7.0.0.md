## Highlights

This is a major release: the full `plan-035` "v7 ground-up" roadmap (Phases 0-6, tasks `T400`-`T511`,
~74 completed tasks across 7 phase boundaries), taking the project from a system that described
itself as beta with no way to check that claim, to one whose maturity claims are mechanically
checked, whose docs are truth-gated in CI, and whose first real closed self-improvement cycle has
been run, caught a false positive, and been hardened against it.

### Truth (Phase 0, Gate G0)

- A CI-enforced version-consistency gate (`scripts/check-version-consistency.py`) now fails any
  build where a non-archived doc references a stale release — the exact problem that let a v6.0.1
  claim survive inside a v6.10.0 repository is now structurally impossible to reintroduce silently.
- The contributor-facing (`CONTRIBUTING.md`) and end-user-facing (`docs/wiki/quick-start.md`) doc
  surfaces were audited and cleanly split; the 6 CWSO deployment guides that didn't belong in this
  repo were relocated to their own project.

### Trustworthy signal (Phase 1, Gate G1)

- `tests/golden/` — a real golden evaluation suite (open + held-out cases), `scripts/scorecard.py`,
  and a `cause x behavior x mechanism` failure-taxonomy scheme give this project, for the first
  time, an *outcome* eval that can actually fail a component — not just a check that the harness
  runs.
- A two-arm Terminal-Bench delta harness (`scripts/tb-delta.sh`) measures emage.code's own
  contribution (`score(treatment) - score(control)`) rather than an absolute score dominated by the
  underlying model, per this roadmap's own explicit critique of leaderboard-chasing.
- Three independent controls protect the held-out set's integrity (a path guard, an evaluator-hash
  tamper check, and a write-scope exclusion) — the PostTrainBench finding this project's own source
  roadmaps cited and under-applied is now actually enforced, not just cited.

### MCP conformance (Phase 2, Gate G2 precursor)

- Every declared MCP server is now schema-validated and conformance-tested across all 7 supported
  platforms, closing the gap where a server could be declared in `servers.yaml` but silently absent
  or malformed in a generated platform projection.

### Maturity ladder (Phase 3, Gate G2)

- The most consequential structural change in this release: promotion from `beta`/`experimental` to
  `stable` now requires mechanically-checked evidence (`implementation/scripts/check-maturity.py`),
  not a self-declaration. A component with an open P0/P1 defect naming it, or without real golden
  suite coverage at its claimed tier, mechanically fails its own maturity check in CI.
- 31 of 77 registry components (20 agents, 4 instructions, 7 skills) earned real, evidence-backed
  `stable` status across three promotion waves. A fourth pass (`T436`) reviewed every non-`stable`
  component and found none warranted `deprecated` — every remaining gap is a live, trackable,
  fixable item, not a dead end.

### Task-tier routing (Phase 4)

- Tasks are now classified `mechanical` vs. `judgment`, gating which task classes a cheaper model
  may be routed to — cost savings are a measured consequence of brief quality, not a blanket
  substitution.

### Persistent memory / RAG (Phase 5, Gate G3)

- `@context-retriever` — a read-only, scope-enforced (general / project / cross-platform) retrieval
  agent over a tree-sitter-indexed knowledge vault, hybrid semantic + lexical + structural ranked.
- Gate G3 formally closed on an honest, twice-independently-remeasured golden-suite comparison: an
  initial real measurement returned a genuine `NO-SHIP` (a pre-existing, arm-agnostic checker bug
  dragging the aggregate down), the checker bug was fixed as its own tracked task, and the
  remeasurement returned `SHIP` — control 21/25 (84.0%), treatment 23/27 (85.2%) — reported exactly
  as measured either time, with the first `NO-SHIP` result never quietly discarded.

### Closed loop (Phase 6, Gate G4) — the headline of this release

- `implementation/runtime/golden_harness/` — a complete, tested, closed-loop pipeline: a failure
  taxonomy queryable by cause/behavior/mechanism; `@meta-improver`, a diff-proposal generator
  architecturally incapable of writing to any real tracked file (proven by static analysis, not
  merely tested); an evaluator-hash tamper-evidence check; a promotion rule; a human MR gate that
  refuses before any git/API call unless a promotion is genuinely approved, with a provably
  nonexistent auto-merge path; a durable kill switch with no programmatic resume path; and a
  lineage-document convention for every accepted change.
- **The loop was run for real** — not a simulation — and did exactly what a gated closed loop is
  supposed to do: it generated a real proposal, evaluated it, and produced a real merge request that
  the human gate correctly caught and did **not** merge, because the "improvement" was not actually
  attributable to the proposal's content. That specific false-positive mechanism (thin, pooled
  evidence and a provenance-confounded comparison) is now closed by three independent, tested
  controls: a per-case minimum-evidence gate, a provenance-homogeneity check, and a qualitative
  positive-effect classification requiring a real, recurring, traceable signal — not just an absence
  of measured regression.
- No component of this closed loop has ever self-merged anything, and the pipeline is now
  architecturally, not just procedurally, prevented from doing so.

## Breaking changes

None. This release is additive: new evaluation infrastructure, new maturity tiers on existing
components (promotion only — nothing was demoted below its prior claimed level), a new memory/RAG
agent that is read-only by construction, and a new closed-loop pipeline that has never merged
anything into this repository's own tracked history. No existing MCP server, platform projection
schema, or installer behavior changed. Confirmed via `node implementation/scripts/sync.mjs --check`
(no drift across 577 files) and the full test suite (`python3 tests/run.py`, 734 tests, 0 failures)
at the time this release was cut.
