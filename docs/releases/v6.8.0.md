## Highlights

### Added

- **Cline platform support** (T352–T357, plan-028-v2): emage.code now ships a seventh supported
  platform. A new `implementation/platforms/cline.json` manifest drives generation of:
  - `.clinerules/` (root-relative) — project rules as `.md` files with `paths`-scoped frontmatter,
    read directly by Cline, no manual copy step needed.
  - `.cline/skills/` — skill definitions, directly usable by Cline.
  - `.cline/mcp.json` — an MCP server **staging file**. Cline's MCP configuration is global
    (`~/.cline/mcp.json` / its own settings panel), not project-local, so this file must be merged
    into your real Cline config rather than auto-applied — see `docs/wiki/cline-setup.md` for a
    worked merge example.
  - Root `AGENTS.md` — Cline auto-detects this file natively (independently re-verified against
    Cline's own docs during T356), so no projection step is needed for it.
  - Installer support: `scripts/install.sh --platform cline` (and `--platform all`), plus
    `Makefile`/`README.md` updated with the new `--platform` value.
  - New `docs/wiki/cline-setup.md`: install steps, Plan/Act-mode guidance mapped onto this repo's
    Plan → Approve → Execute lifecycle, the MCP merge-not-overwrite walkthrough, and a
    troubleshooting section.

  **Scope limitation, stated plainly:** this release does **not** include Cline subagent
  (`.cline/agents/`) or slash-command projection. emage.code ships 27 subagents and 18 slash
  commands to other platforms, but as of this writing no confirmed on-disk format for
  Cline-native subagents or slash commands exists in Cline's documentation, and emage.code does
  not invent one. This is an intentional, documented scope boundary (see `docs/wiki/cline-setup.md`
  § "Scope note"), not a defect — it will be revisited if Cline documents a format for either.

## Breaking changes

- None. T352–T357 only added new files/capabilities: a new platform manifest
  (`implementation/platforms/cline.json`), a new generated output tree
  (`implementation/.cline/`, `implementation/.clinerules/`), and additive engine changes to
  `implementation/scripts/sync.mjs` gated behind manifest opt-in flags (`rootRelative: true`, an
  optional `fileMap.agents`/`.commands` that's skipped cleanly when a manifest omits them — a
  generic behavior, not Cline-specific). None of these paths alter output for any of the other six
  existing platforms, confirmed by T353's and T357's own verification (`sync.mjs --check`: 0 drift
  across all platforms before and after; T357's fresh-checkout re-verification found the same).
