# Release v10.0.0

## Summary

v10.0.0 is a MAJOR release of the emage.code harness since v9.0.0. `/prepare-release` is no longer installed into target projects, `context-retriever` finds its index through the git remote, and the two security servers refuse what they used to accept. The release gate reads its document with a real Markdown parser, and the CI image moves to Python 3.12.16. Read the Migration Guide before you run `--update`: M-1 and M-3 can need action first, and **`--projections-only` must not be your step from v9 to v10** (M-2).

## Install

Latest release: v10.0.0

Install with the installer from a clone of this repository:

```bash
git clone https://gitlab.com/em-age/emage.code.git
cd emage.code
scripts/install.sh --target <your-project> --platform <name>
```

| Platform | `--platform` value |
|----------|-------------------|
| GitHub Copilot (VS Code) | `github` |
| Gemini CLI | `gemini` |
| Opencode | `opencode` |
| Pi | `pi` |
| Claude Code | `claude-code` |
| Cline | `cline` |
| All platforms | `all` |

Update an existing install: add `--update`. `scripts/install.sh --help` lists every option. If you run v8.x or older, first read the Migration Guide of v9.0.0 (`docs/releases/v9.0.0.md`, in the emage.code repository and at the `v9.0.0` tag). Cursor support was removed in v9.0.0.

Set the MCP environment variables named in the generated MCP config, then run
`/new-project "Your idea"` in your assistant.

## Highlights

- **`/prepare-release` leaves target projects (T725).** Every install mode deletes it on five platform paths, and `--update` or `--projections-only` also deletes a renamed copy inside a platform tree. Read M-1 first if you use it.
- **`context-retriever` reads its index from a path taken from the git remote (T722).** After `--update`, an index built under v9 is not read and the server does not start until you rebuild it (M-2). This closes the hard-coded directory name of v9.0.0's K-5.
- **`security-audit` and `poc-security-audit` are stricter (T714).** A broad root stops them at start, an index set only in the environment refuses the audit, and child tools no longer inherit the server's environment (M-3). This is a control tightened, not a regression.
- **The release gate reads the document with `markdown-it-py` (T739, T747, T749), and every gate command runs with an allowlisted environment (T750).** For authors of this repository's releases (M-7). A target project receives neither the gate nor the template.
- **The CI image moves to Python 3.12.16 (T765, SEC-T756-01).** The earlier image lacked the block on the compromised eMudhra certificate keys, CVE-2026-115557. See K-34 for what was checked and what this does not fix.
- **Accepted risks are for one release only (T720, T735; ADR-011, ADR-012).** Five `SECURITY:MEDIUM` findings ship in this release under the user's acceptance for v10.0.0: K-15, K-16 (two ids), K-28 and K-29.

## Breaking changes

Counting rule (release manager): this section lists every task that `docs/artifacts/release-v10-audit-v1.md` § 2.3 classifies as breaking, one entry per task (5 entries: T725, T722, T714 for a target; T726, T739 for a checkout of this repository). The verdict count equals the number of entries listed here. Behaviour changes are in M-8 and are not counted.

- **A-01** `/prepare-release` is no longer installed into a target, and all three install modes delete an existing copy. Commands declare `audience: authoring | target | both`, and the generator stops on a command without it (T725, M-1, M-5).
- **A-02** `context-retriever`: every generated config drops `--index-dir`, and the server reads an index path derived from the git remote. A v9 index is not read, and the server does not start without that index or without a remote. On Copilot the `context-retriever` agent loses its `context-retriever/retrieve` grant (T722, M-2, M-4, M-5).
- **A-03** `security-audit` and `poc-security-audit` refuse a broad allowed root and an environment-only package index, and child tools lose inherited credentials (T714, M-3).
- **A-04** (checkout only) CWSO helper scripts: `sia-executor.py --jwt-secret` is removed, and `cwso-deploy-helper.sh export --secret-file` also needs `--print-secret` (T726, M-6).
- **A-05** (checkout only) `scripts/verify-release-docs.py` exits 1 without `markdown-it-py` (T739, M-7).

## Migration Guide

**Migration from v9.0.0 to v10.0.0. Use `--update`, not `--projections-only`.** `--projections-only` refreshes the generated configs but not `implementation/runtime/`, so the v9 `context-retriever` server, which still requires `--index-dir`, runs without it and exits with `error: the following arguments are required: --index-dir` (observed on a throwaway target, claude-code). `--update` and a plain install refresh both.

Do this in order:

1. **Before the update:** Commit or back up your project, including any file you keep inside a platform tree: `--update` replaces those trees. Then M-1 if you use `/prepare-release`; check M-3 if your project root is `$HOME` or your package index or registry credential lives only in an environment variable.
2. Run the update. A `--dry-run` first prints the `rm` of `/prepare-release`.

   ```bash
   cd <emage.code clone>
   git fetch --tags && git checkout v10.0.0
   scripts/install.sh --target <your-project> --platform <name> --update
   ```

3. **After the update:** M-2 if you built an index; M-3 if it applies; M-4 if you defined your own `context-retriever` server on Copilot.

M-5 is for a fork that authors its own knowledge. M-6 and M-7 are for someone working from an emage.code checkout. M-8 needs no action. On a v9 target the audit's `--update` changed 99 files, in the platform trees, `.mcp.json` and `implementation/runtime/`; it changed nothing in `docs/`, `AGENTS.md` or `CLAUDE.md`.

**What a target does not receive.** A target holds no `scripts/`, `docs/releases/`, `ci/`, `.gitlab-ci.yml`, `CONTRIBUTING.md`, `CHANGELOG.md`, `implementation/scripts/`, `implementation/registry/`, `implementation/PREREQUISITES.md` or `implementation/SECURITY.md`. Any `scripts/` command in this document runs from an emage.code clone, and any `docs/releases/` path and those two `implementation/` documents are in the emage.code repository.

**Cursor: nothing changes in this release.** No line of `scripts/install.sh` points to this document, so this document carries no Cursor item. The installer's Cursor notices keep pointing to the older documents: `scripts/install.sh:187` and `:1301` name the Cursor migration item in `docs/releases/v9.0.0.md`, and `:1297-1300` hold the advice on `.cursor/mcp.json`, which names M-9 in `docs/releases/v8.0.0.md`.

### M-1. `/prepare-release` is no longer installed (T725, TD-T671-P5). Before `--update`, if you use it

- It is removed from a target on `.claude/commands/prepare-release.md`, `.gemini/commands/prepare-release.md`, `.opencode/commands/prepare-release.md`, `.pi/prompts/prepare-release.md` and `.github/prompts/prepare-release.prompt.md`.
- All three modes delete an existing copy: `--update`, `--projections-only` and a plain install. A dry run prints the `rm`.
- **A copy under another file name inside a platform tree is deleted too.** `.claude/commands/my-prepare-release.md` was deleted by both `--update` and `--projections-only`, and no line of the log named it. Only a plain install left it. This is the known `rsync -a --delete` of those trees: `commands/` is not a spared path.
- **If you want to keep the command:** keep your copy **outside** the platform trees, and copy it back after each install. It names paths a target does not have.
- An authoring checkout, a directory holding `implementation/registry/index.json`, keeps the command.
- `.generated-manifest.json` gains `authoringOnly`. Its `files` list still names the withheld path in a target (K-33).

### M-2. `context-retriever`: the index location now comes from the git remote (T722, TD-T671-K5). After `--update`, if you built an index

- Every generated config drops `--index-dir implementation/runtime/memory/_index/em-age-emage.code`. The server now reads `implementation/runtime/memory/_index/<org>-<repo>`, lower case, from the workspace's git remote `origin` (`acme/widget` gives `_index/acme-widget`). On a nested group only the last two parts of the path count: `https://gitlab.com/group/sub/repo.git` gives `sub/repo` and `_index/sub-repo`.
- **A v9 index is not read after the update, and the server does not start.** v9's installer told you to match the `--index-dir` in the config, so a v9 target built its index in the old path. The load then fails with `FileNotFoundError`, in that example on `_index/acme-widget/manifest.json`.
- **Action:** rebuild it. First install `implementation/runtime/memory/requirements.txt` into the same environment: the install note names only the server's dependencies, and with those alone the build exits 1 with `ModuleNotFoundError: No module named 'yaml'`. With that file installed it exits 0 (run by QA, T760). Then run the command the installer prints (`scripts/install.sh:1745-1747`):

  ```bash
  python3 -m implementation.runtime.memory.build \
      --project-id <org>/<repo> --own-repo-root . --general-repo-root . \
      --output-dir implementation/runtime/memory/_index/<org>-<repo>
  ```

  Use lower case in both values, and in your entries' `project_id`. The server lower-cases the remote and compares exactly, so with `Acme/Widget` the build reports `wrote 1 chunks`, the server starts, and `retrieve` returns an empty result with no error (run by QA).
- **What was run.** QA made a real retrieval on v10 over stdio (`initialize`, `tools/list`, `retrieve`) on a one-chunk project-scope entry, and it returned the chunk. QA's stdio calls came from a small script, and no assistant ran **(unverified)**. An index built at `_index/em-age-emage.code` and moved to `_index/acme-widget`, instead of rebuilt, loaded and answered. QA built it with this tree's `build.py`, which is unchanged since v9.0.0, so moving an index really built by a v9 install stays **(unverified)**.
- **With no git remote the server now fails at start** with `RemoteResolutionError`. Under v9 it got past start with a given index directory and failed at the first query (inferred from the code).
- **A hand-set `--index-dir` under the generated name is replaced with no note.** To use another location, pass `--index-dir` in an entry under a name the generator does not own; `--update` kept such an entry (observed by QA); that entry was not started **(unverified)**.
- **Unrecognised remote (SEC-T722-04):** the start error for an unrecognised remote prints the URL, so remove credentials from a remote URL.
- **Do not use `--projections-only` for this step**, as the top of this guide says.

### M-3. `security-audit` and `poc-security-audit` refuse what they accepted (T714; SEV-T690-04, SEC-T714-01, SEC-T714-03). After `--update`; check before if one applies

`implementation/runtime/` is refreshed by `--update` and a plain install, not by `--projections-only`.

- **A broad root stops the start.** An `allowed_root` of `/`, `$HOME` or an ancestor of `$HOME` raises `PathValidationError`, so a project whose root is `$HOME` loses both servers. **Action:** launch from a workspace directory below it.
- **An index set only in the environment refuses the audit.** `run_pip_audit` refuses while `PIP_INDEX_URL`, `PIP_EXTRA_INDEX_URL` or `PIP_FIND_LINKS`, or a `PIP_AUDIT_` form, is set, and `run_npm_audit` refuses while any `npm_config_*registry` is set. **Action:** move the setting into `pip.conf` or `.npmrc`, unset the variable and restart the server.
- **Child tools no longer inherit the server's environment.** A registry credential held only in a variable is no longer seen. By the module's docstring a NuGet feed then fails with an authentication error, which was not run **(unverified)**. **Action:** keep such credentials in the tool's own file.
- **`grep_content` refuses more names:** `.netrc`, `.npmrc`, `.pgpass`, `.git-credentials`, `.aws`, `*.p12`, `*.pfx`, `*.kdbx`. No action.

No credential in a child's environment is the point of this change. The guards were run by calling their functions in an updated target, and QA started both servers with `HOME` set to the target (exit 1, `PathValidationError`), not through an MCP call from a live client.

### M-4. Copilot: the `context-retriever` agent loses `context-retriever/retrieve` (T722, SEV-T690-06). After `--update`, silently

`tools:` becomes `[read, search]` in `.github/agents/context-retriever.agent.md`. Copilot's generated config has no such server, so the grant could be met only by a server you defined yourself. If you did, you lose the tool until an agent file of yours grants it; an edit to the generated file does not survive `--update`. It is the only agent token dropped on any platform. Whether the agent is useful without it on Copilot **(unverified)**.

### M-5. Generator, for a fork that authors its own knowledge (T722, T725; SEC-T684-02)

- `sync.mjs` stops on a command without `audience: authoring | target | both`.
- `mcp.outputFile` must lie under the manifest's `outputDir`, or be exactly `.mcp.json` or `.vscode/mcp.json` at the root. An MCP file may not lie in another manifest's removal tree.
- An `mcp__<server>__` token of a server that `servers.yaml` defines but a platform does not carry is left out of that platform's agent.

### M-7. Release authors of this repository. Not for a target

The rules are in `CONTRIBUTING.md` § Releasing. A target receives neither `scripts/verify-release-docs.py` nor `docs/releases/_template.md`. Batches G (plan-131), S (plan-140, plan-143) and T (plan-142), with plans 135, 136 and 138, change what an author sees:

- **No parser, no gate (T739).** Every gate run exits 1 without `markdown-it-py` and prints the install command. Use it in a virtual environment: `python3 -m pip install --require-hashes --only-binary=:all: -r ci/requirements-release.txt`. A system package may be another version; the job's locked run decides.
- **`CHANGELOG.md` entries.** They now show `\#42`, `\@user` and URLs in backticks in their source, and `(#42)` no longer links to the issue. How GitLab renders them has not been observed in a Release **(unverified)**.
- **How the Cursor item is found.** The blank-line rule is gone, and `## Migration Guide <!-- x -->` now counts. The section is the first top-level level 2 heading whose text is exactly `Migration Guide`, in ATX or setext form, up to the next top-level level 1 or 2 heading. A heading inside a blockquote or a list neither opens nor ends it. The item, with the case-sensitive word `Cursor` in its text, is either a top-level heading of level 3 to 6, or a paragraph that opens with a `**` strong span, top-level or with only list containers around it, and only the text inside that span counts. `__bold__`, an anchor in a blockquote and a heading in a list do not count. A bold lead must open its own paragraph, so a blank line is still what you need there.
- **Refused line breaks.** The tag's release document, the three marker files and `scripts/install.sh` may not contain `\v \f \x1c-\x1e \x85 U+2028 U+2029`. `scripts/install.sh` may hold no CR, CRLF included; a release document may keep CRLF.
- **Refused documents.** A release document is refused, by path, in this order: over 131072 characters; a line over 65536; a front matter opening (`---`, `+++` or `;;;`, optionally after a BOM, white space or a `coding:` line); reaching the parser's nesting limit of 20 levels, where a list item counts as two; HTML other than comments, anywhere, at any depth.
- **Placeholders.** Prose such as `<your-project>` outside code is refused, because the parser decides what is HTML. A placeholder in a code span passes the gate, so replace it with its value; a code span is for literal text that keeps its angle brackets. The gate does not read other placeholders (SEC-T751-09), so a reader must check them.
- **Checked files must be valid UTF-8.** The gate names the path and the offset, never the content. `scripts/check-version-consistency.py` reads strictly too, so a committed non-UTF-8 `.md` outside its exclusions blocks a release.
- **The verdict check reads the parser's tokens.** The verdict section must be a real top-level heading, and it ends at the next top-level level 1 or 2 heading with text, in either form, so `Text` above `---` ends it. Only closed backtick fences are skipped. A second real heading of that name is an error.
- **New CI rules.** A new job in `.gitlab-ci.yml` needs an `if` from `NOT_TAG_CONDITIONS`. No tag job may carry `allow_failure`. A new CI/CD variable stays out of every gate command unless it takes `--keep` and a pin edit. A change to the `release` job's script line needs the same edit in `RELEASE_COMMAND`. `scripts/run-allowlisted.py` is a code path that every gate command passes through and no pin reads, so a change to it is for code review.

### M-8. Behaviour changes to brief your team on. No action

The verdict gains `Issued at commit` and `Independent check`, and the Conditions block `grade=` and `release=`.

The Cursor notice has one line per case. An unedited Opencode entry no longer draws a false "differs" note. The install note on the `context-retriever` index no longer tells you to match an `--index-dir` that is gone.

## Known Issues

### Accepted for v10.0.0 only

These `SECURITY:MEDIUM` findings ship unfixed. The user accepted each one for v10.0.0, and the words and full plan belong to the verdict's Conditions. An acceptance covers this release only: each finding returns at the next release, to be fixed or accepted again. **For SEC-T660-01 and the SEC-T658-01 remainder, the earlier plan's deadline has passed. The rules do not say whether a new acceptance cures a passed deadline**, and the questions put to the user said so.

- **K-16** GitLab token, SEC-T660-01 and SEC-T665-01: **an agent's shell running as you can read the GitLab token, and can merge, tag, release or push with it.** All seven holder roles have named tool sets, but that narrows a tool list and is not a credential boundary: six of them hold `execute`. `GITLAB_PERMISSION_MODE=modify` does not stop a shell, any same-user process can read the token file, and tmpfs can swap unless swap is encrypted. One shared Developer-level token serves every role (SEC-T665-07, DEC-T681-1). This is mitigated, not closed: T665 and T689 delivered the token file, the mode and the in-memory default as done work, separate from this plan. **Fix: none possible in the harness, and none is planned; this plan does not end the finding.** Closure takes an isolated user, container or VM, which you must set up.
