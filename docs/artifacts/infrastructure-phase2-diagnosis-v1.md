# Phase 2 Infrastructure Diagnosis & Remediation Report

**Date:** 2026-06-23
**Task:** T228 - SIA Dispatch Live Integration
**Status:** Infrastructure gaps identified and fixed

---

## Executive Summary

The Phase 2 rollout infrastructure was partially deployed but **disabled key execution components by default**. Tasks could be submitted via `/rollout/task/submit` but would never execute because the orchestrator had no **gateway** wired to manage session execution.

The diagnostic evidence from `dispatch-test-sia.py` revealed:
- ✅ Dispatch API operational (tasks created successfully)
- ✅ Task state persisted (can poll status)
- ❌ Tasks stuck in `running` state indefinitely
- ❌ Zero registered nodes / zero execution callback
- ❌ Zero partial results / trajectories / parquet files

**Root Cause:** Three CWSO orchestrator feature flags were disabled:
1. `CWSO_ROLLOUT_GATEWAY_STAGING_ENABLED` (session execution gateway)
2. `CWSO_ROLLOUT_EVALUATOR_REGISTRY_ENABLED` (evaluation callbacks)
3. `CWSO_ROLLOUT_TRAJECTORY_BUILDER_ENABLED` (Parquet trajectory capture)

**Status:** Fixed in `deploy/t226-phase2.env` and `deploy/docker-compose-t226.yml`

## Root Cause Analysis

### How Phase 2 Execution Should Work

1. **Dispatcher** receives `POST /rollout/task/submit` with task_spec
2. **Session Manager** creates a rollout session, marks as `queued`
3. **Gateway Staging** (INIT pool) prepares execution environment
4. **Session Executor** (worker) is assigned to READY pool
5. **Executor Process** runs the SIA target with sample configurations
6. **Callback Handler** receives `/callbacks/session_result` with outcomes
7. **Trajectory Builder** captures LLM calls → Parquet files
8. **Reward Engine** (T224) attaches evaluation rewards
9. **Session Manager** marks task as `completed`
10. **Merge Engine** (T225) integrates results into codebase

### What Was Missing (Pre-Fix)

The CWSO orchestrator had steps 1-2 working but **steps 3-9 were disabled by default**.

**Three Feature Flags Default to `false`:**

```go
// orchestrator/internal/config/config.go lines 79, 86, 90
RolloutGatewayStagingEnabled         bool     // ← DISABLED (0 registered nodes!)
RolloutEvaluatorRegistryEnabled      bool     // ← DISABLED (no callbacks)
RolloutTrajectoryBuilderEnabled      bool     // ← DISABLED (no Parquet files)
```

**Corresponding Environment Variables:**

```bash
CWSO_ROLLOUT_GATEWAY_STAGING_ENABLED=false        # default
CWSO_ROLLOUT_EVALUATOR_REGISTRY_ENABLED=false     # default
CWSO_ROLLOUT_TRAJECTORY_BUILDER_ENABLED=false     # default
```

**Prior Deployment (t226-phase2.env):**
```bash
# These flags were MISSING entirely → defaults to false
# CWSO_ROLLOUT_GATEWAY_STAGING_ENABLED was not set
# CWSO_ROLLOUT_EVALUATOR_REGISTRY_ENABLED was not set
# CWSO_ROLLOUT_TRAJECTORY_BUILDER_ENABLED was not set
```

## Fix Applied

### Change 1: Enable Gateway Staging in docker-compose-t226.yml

```yaml
orchestrator:
  environment:
    # Phase 2: Execution gateway & trajectory builder (T146, T149)
    CWSO_ROLLOUT_GATEWAY_STAGING_ENABLED: "${CWSO_ROLLOUT_GATEWAY_STAGING_ENABLED:-true}"
    CWSO_ROLLOUT_EVALUATOR_REGISTRY_ENABLED: "${CWSO_ROLLOUT_EVALUATOR_REGISTRY_ENABLED:-true}"
    CWSO_ROLLOUT_TRAJECTORY_BUILDER_ENABLED: "${CWSO_ROLLOUT_TRAJECTORY_BUILDER_ENABLED:-true}"
    CWSO_ROLLOUT_TRAJECTORY_BUILDER_STRATEGY: "${CWSO_ROLLOUT_TRAJECTORY_BUILDER_STRATEGY:-per_request}"
```

### Change 2: Document Phase 2 Feature Flags in t226-phase2.env

```bash
# ==============================================================================
# Phase 2: Execution Gateway & Trajectory Builder
# ==============================================================================

# Enable session execution gateway (INIT/READY/RUNNING/POSTRUN pools)
CWSO_ROLLOUT_GATEWAY_STAGING_ENABLED=true

# Enable post-run evaluator registry
CWSO_ROLLOUT_EVALUATOR_REGISTRY_ENABLED=true

# Enable trajectory builder for Parquet capture
CWSO_ROLLOUT_TRAJECTORY_BUILDER_ENABLED=true

# Trajectory builder strategy: per_request or prefix_merge
CWSO_ROLLOUT_TRAJECTORY_BUILDER_STRATEGY=per_request
```

### What Each Fix Enables

| Feature | Env Var | Code Path | Effect |
|---------|---------|-----------|--------|
| **Gateway Staging** | `CWSO_ROLLOUT_GATEWAY_STAGING_ENABLED` | `orchestrator/internal/server/server.go:307` | Creates INIT/READY/RUNNING/POSTRUN pools; registers executor nodes; advances task lifecycle |
| **Evaluator Registry** | `CWSO_ROLLOUT_EVALUATOR_REGISTRY_ENABLED` | `orchestrator/internal/server/server.go:319` | Enables `/callbacks/session_result` handler; allows reward attachment via MCP tools |
| **Trajectory Builder** | `CWSO_ROLLOUT_TRAJECTORY_BUILDER_ENABLED` | `orchestrator/internal/server/server.go:322` | Enables Parquet capture; writes trajectory files to `/tmp/t226-parquet-store` |

## Expected Behavior Post-Fix

### With Gateway Enabled

When `CWSO_ROLLOUT_GATEWAY_STAGING_ENABLED=true`, the orchestrator will:

1. **Create executor pools** at startup
2. **Register node capacity** with gateway (registered_nodes > 0)
3. **Assign sessions** to READY pool
4. **Advance task state** through RUNNING → COMPLETED
5. **Invoke callbacks** when sessions complete
6. **Capture trajectories** in Parquet format

## Summary

**Blocker:** Phase 2 rollout infrastructure was partially deployed but execution gateway disabled.

**Evidence:** Diagnostic JSON showed 0 registered nodes, tasks stuck in running, zero partial results/trajectories/parquet files.

**Root Cause:** Three CWSO feature flags (`ROLLOUT_GATEWAY_STAGING`, `EVALUATOR_REGISTRY`, `TRAJECTORY_BUILDER`) default to false and were not enabled in deployment config.

**Fix Applied:** Enabled all three flags in `docker-compose-t226.yml` and documented in `t226-phase2.env`.

**Expected Outcome:** After deployment, tasks will progress through execution gateway pools → completion → evaluation → parquet capture.

**Next Steps:** Deploy updated docker-compose, re-run dispatch test, verify task completion and trajectory collection.
