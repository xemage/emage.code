## Suggested text for Known issues

> Playwright (`playwright`, core). The entry is launched headless, isolated, with the browser sandbox, with service workers blocked and with a `--blocked-origins` list for loopback, private, link-local and carrier-grade-NAT ranges. This is not a security boundary: it does not cover redirects (an allowed page can redirect to an internal address and the page content is returned to the model), WebSockets, DNS names that resolve to internal addresses (for example wildcard DNS names), or the `browser_run_code_unsafe` tool, which runs code on the host and is not removable in 0.0.83. Pages the agent opens can carry prompt-injection text. The same list blocks local-app URLs, so E2E testing of a local dev server needs a user-owned entry. The `fetch` server was removed (SEC-T646-01); an installed config without a provenance sidecar keeps it until it is removed by hand or with `--force-prune-keys fetch`. Egress control through a filtering proxy (`--proxy-server`) is the tested closure and is not shipped. Evidence: `docs/artifacts/fetch-replacement-evaluation-v1.md`. (If SEC-T655-01 is fixed before the release, drop the sentence on the four agents; the original text named qa-engineer, frontend-developer, poc-qa-engineer and demo-agent as holders of the whole server.)
