- **Non-Playwright lines**: none of the read-only roles gained a write tool (tech-lead, product-owner and the technical writers hold no MCP token; security-engineer holds only the four `security-audit` tools; poc-security-engineer holds `security-audit/grep_content` and two `poc-security-audit` tools; `security-audit`, `poc-security-audit` and `context-retriever` are `extended` servers that Copilot's `.vscode/mcp.json` does not carry, so those tokens stay inert there as before).
- **Globs**: Opencode `gitlab_*`, `memory_*`, `sequential-thinking_*` would also match a user server whose cleaned name starts with that prefix (none ships); Pi `mcp__gitlab__*` cannot match `mcp__gitlab_ee__…`; Copilot `gitlab/*` is exact per server.
- **Generator safety**: the `hasOwnProperty` guard blocks `__proto__`/`constructor` as a style name; an unknown style fails the run and the test pins the stderr text; every new regex is a linear character class (no ReDoS); `underscore`/`pi` output is restricted to `[A-Za-z0-9_-]`; no injection path.
- **Tests**: the mapping tests re-implement the rules independently and compare them with literal vendor examples, a real generator run on a fixture root and every shipped projection of `github`, `opencode` and `pi`; the grant-set tests pin exact per-agent sets and holders across five projections.

## Required Known-issues text (replaces the T655 suggestion; owner release-manager, T645)

> Playwright (`playwright`, core). The entry is launched headless, isolated, with the browser sandbox, with service workers blocked, with `--no-webmcp` and with a `--blocked-origins` list for loopback, private, link-local and carrier-grade-NAT ranges. This is not a security boundary: it does not cover redirects (an allowed page can redirect to an internal address and the page content is returned to the model), WebSockets, DNS names that resolve to internal addresses, or the `browser_run_code_unsafe` tool, which runs code on the host and cannot be removed in 0.0.83. The four agents qa-engineer, frontend-developer, poc-qa-engineer and demo-agent hold named, non-`unsafe` Playwright tools instead of the whole server. That narrowing is in force on Claude Code and, according to the vendor documentation (not observed in a live run), on GitHub Copilot/VS Code, and on Pi only when the agent file is passed to `pi --tools` and the agent lists an `mcp__` tool. It is **not in force on Opencode, Gemini CLI and Cursor**, where an agent's tool list does not restrict MCP tools: there every agent, not only these four, can call every tool of every configured MCP server, including `browser_run_code_unsafe`, `browser_evaluate`, `browser_file_upload` and the GitLab write tools. A user-owned `playwright-local` entry has no origin restriction and is reachable the same way. Pages the agent opens can carry prompt-injection text. The same blocked list blocks local-app URLs. On GitHub Copilot/VS Code the agents' MCP grants (`gitlab`, `memory`, `sequential-thinking`, `playwright`) take effect for the first time in this release; before, the tokens were ignored. Egress control through a filtering proxy (`--proxy-server`) is the tested closure and is not shipped. The `fetch` server was removed (SEC-T646-01); an installed config without a provenance sidecar keeps it until it is removed by hand or with `--force-prune-keys fetch`. Evidence: `docs/artifacts/fetch-replacement-evaluation-v1.md`, `docs/artifacts/mcp-tool-name-mapping-v1.md`.
